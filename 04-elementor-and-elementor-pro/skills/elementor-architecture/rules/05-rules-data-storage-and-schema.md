# قوانین مهندسی دسته ۵: ذخیره‌سازی داده‌ها و اسکیماهای دیتابیس (Data Storage & Schema Rules)

این سند قوانین مربوط به دستکاری، خواندن، نوشتن و اعتبارسنجی داده‌های المنتور در جدول‌های `wp_postmeta` و جداول اختصاصی را تبیین می‌کند.

---

## ۱. قوانین متای پست `_elementor_data`
1. **ساختار JSON خام:** داده‌های `_elementor_data` به صورت JSON کدگذاری‌شده نگهداری می‌شوند. در صورت خواندن با `get_post_meta($post_id, '_elementor_data', true)`، اگر خروجی رشته بود، باید با `json_decode( $data, true )` به آرایه PHP تبدیل شود.
2. **سالم‌سازی هنگام بازنویسی:** هرگز نباید داده‌های `_elementor_data` را به صورت دستی و با کوئری‌های SQL بدون اعتبارسنجی آپدیت کرد؛ تغییر دستی باعث ابطال کش CSS و از دست رفتن شناسه‌های المان‌ها (`id`) می‌شود.
3. **همگام‌سازی با نسخه و نوع سند:** همزمان با ثبت `_elementor_data`، متای `_elementor_edit_mode = 'builder'` و `_elementor_template_type` باید به‌درستی تنظیم شوند.

---

## ۲. قوانین جداول اختصاصی لیدها و سابمیشن‌ها (`wp_e_submissions`)
1. داده‌های فرم‌های المنتور نباید در `wp_posts` ثبت شوند؛ بلکه باید با روال استاندارد ماژول فرم پرو در جداول زیر ذخیره شوند:
   - `wp_e_submissions`: متادیتای سابمیشن.
   - `wp_e_submissions_values`: مقادیر ورودی فیلدها.
   - `wp_e_submissions_actions_log`: لاگ وضعیت وب‌هوک‌ها و ایمیل‌ها.
2. رعایت حریم خصوصی (GDPR): آی‌پی و متادیتای کاربر در صورتی که کاربر تنظیمات ناشناس‌سازی را فعال کرده باشد، باید با متدهای هشینگ سنیتایز شوند.

---

## ۳. قوانین کش استایل و CSS
1. پس از هر تغییر برنامه‌نویسی در دیتای المان‌های صفحه، کش فایل CSS باید پاک شود تا المنتور در لود بعدی فایل `post-{id}.css` را بازتولید کند:
   ```php
   \Elementor\Plugin::$instance->files_manager->clear_cache();
   ```

---

## ۴. قانون الزام بازگشت به سورس‌کد (Source Code Fallback Directive)
> [!IMPORTANT]
> در صورت نیاز به درک اسکیمای جداول دیتابیس، ساختار کوئری‌ها یا ارتقای دیتابیس، عامل باید مستقیماً سورس فایل‌های `elementor/core/base/db.php`، `elementor-pro/modules/forms/submissions/` و `elementor/core/upgrade/` را بررسی کند.
